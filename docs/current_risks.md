# Текущие риски и план стабилизации

Статус на 2026-08-01: проект пригоден для разработки и тестирования, но не для
выпуска повторяемых клиентских отчётов. Документ фиксирует ограничения текущей
реализации; он не означает, что перечисленные меры уже реализованы.

## Блокирующие риски

| ID | Проблема | Влияние | Следующее изменение | Статус |
|---|---|---|---|---|
| P1-01 | Артефакты разных запусков могут смешиваться | Старые данные попадают в новые метрики и отчёт | Изолировать run, публиковать stage атомарно | Отложено: код/архитектура |
| P1-02 | `source`, `table` и `capability` описаны несогласованно | Проверки ошибочно запускаются или пропускаются | Ввести проверяемый реестр производителей | Отложено: контракт |
| P1-03 | Постоянное ограничение D11 не применяется | Завышается тип и уверенность результата | Исправить degradation и добавить сквозной тест | Отложено: код |
| P1-04 | Ошибка compute не блокирует успешное завершение | Сохраняется старая метрика после сбоя | Разделить недоступность источника и внутреннюю ошибку | Отложено: код |
| P1-05 | Analyze удаляет предыдущий draft до успешной замены | Сбой внешнего вызова уничтожает пригодный черновик | Временный каталог и атомарная публикация | Отложено: код |
| P1-06 | Нет реализованного privacy-контракта для LLM | Возможна передача лишних клиентских данных | Allowlist, redaction, consent и retention | Блокирует live analyze |
| P1-07 | CRM-шаблон не соответствует импорту | Строки шаблона могут молча отклоняться | Согласовать headers/mapping и добавить E2E-тест | Отложено: код/шаблон |
| P1-08 | Корень содержит вложенный Git без `.gitmodules` | Обычный clone не воспроизводит проект | Принять отдельное решение о Git-топологии | Отложено: ADR |

## Временные эксплуатационные гейты

- Не выпускать клиентский `report` до закрытия P1-01, P1-03, P1-04 и P1-05.
- Не запускать `analyze` на реальных данных без документированного согласия
  клиента и ручной проверки отправляемого пакета.
- Перед каждой проверкой фиксировать commit обоих репозиториев и сохранять
  `git status`; результаты грязного дерева не считать воспроизводимыми.
- Не считать отсутствие падения CLI доказательством успешности compute:
  проверять свежесть и состав каждого metric-артефакта вручную.
- Не использовать неизменённый CRM-файл из `clients/_template` до исправления
  контракта импорта.

## Безопасная последовательность следующих задач

1. Исправить D11 и CRM-шаблон отдельными микрозадачами с целевыми тестами.
2. Сделать ошибки compute фатальными и защитить предыдущий draft.
3. Ввести идентичность запуска и атомарную публикацию артефактов.
4. После стабилизации контрактов добавить CI и проверку producer/requirement.
5. Только затем выбирать целевую Git-топологию и дробить крупные модули.
