# Безопасность и конфиденциальность

Статус: временная политика для разработки. Техническое принуждение описанных
правил реализовано не полностью, поэтому документ нельзя трактовать как
гарантию соответствия требованиям законодательства или договора с клиентом.

## Действующие ограничения

- Секреты хранятся только в `clients/<name>/.env`; их запрещено добавлять в
  код, логи, документацию и Git.
- Клиентские данные и идентификаторы не должны находиться вне `clients/<name>/`.
- Стадии `extract`, `transform` и `compute` не используют LLM.
- Текущий `analyze` способен передать внешнему ProxyAPI содержимое YAML из
  `inputs/`; программный allowlist и автоматическое удаление PII отсутствуют.

## Гейт для внешнего LLM

До реализации технического privacy-контракта `analyze` на реальном клиенте
разрешён только при одновременном выполнении условий:

1. Получено и сохранено согласие клиента на передачу данных указанному
   поставщику модели.
2. Вручную проверен фактический пакет отправки и удалены PII, секреты и поля,
   не необходимые для анализа.
3. Зафиксированы поставщик, регион обработки, срок хранения, стоимость и лицо,
   ответственное за удаление данных.
4. Ключ поставщика загружается из `clients/<name>/.env`, а не из общей среды
   проекта.

Если хотя бы одно условие не выполнено, `analyze` не запускается; допустимы
только детерминированные стадии и локальная ручная проверка метрик.

## Требования к будущей реализации

- Явный allowlist передаваемых полей и denylist секретов/PII.
- Dry-run с сохранением локального redacted-пакета для утверждения аналитиком.
- Машинная фиксация consent, поставщика, модели, времени и hash пакета.
- Настраиваемые retention и удаление локальных/внешних промежуточных данных.
- Проверка истории Git специализированным secret/PII scanner до публикации.
