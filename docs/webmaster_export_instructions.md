# Ручная выгрузка Яндекс.Вебмастера — инструкция для оператора

Относится к `sources.webmaster.mode: "manual"` (см. `clients/<name>/config.yaml`).
Экстрактор — `src/extract/webmaster_manual.py`.

## Куда класть файл

```
inputs/manual_exports/webmaster/
  webmaster_export.csv   — единственный файл, за ВЕСЬ период сразу
```

В отличие от GSC, здесь **нет** папок `YYYY-MM/` и нет отдельных файлов на
каждый месяц. Один клиент = один CSV-файл (имя задаётся
`manual_export_file`, по умолчанию `webmaster_export.csv`), который
целиком лежит в `manual_export_dir` (по умолчанию
`inputs/manual_exports/webmaster`). Все месяцы истории — колонки внутри
этого одного файла (см. ниже).

## Формат файла (wide) — что именно ожидает парсер

Одна строка = одна пара (запрос × страница). Месяцы развёрнуты в колонки
с префиксом `YYYY-MM_`:

```
Query | Url | 2026-05_shows | 2026-05_position | 2026-05_demand | 2026-05_ctr | 2026-05_clicks | 2026-04_shows | ...
```

На каждый месяц истории — свой блок из пяти колонок:
`{YYYY-MM}_shows`, `{YYYY-MM}_position`, `{YYYY-MM}_demand`,
`{YYYY-MM}_ctr`, `{YYYY-MM}_clicks`. Порядок колонок и порядок месяцев
слева направо не важен — парсер находит месяцы по регэкспу
`{YYYY-MM}_shows` в заголовке и читает остальные метрики того же месяца
по такому же префиксу.

## Как собрать файл

1. В интерфейсе Яндекс.Вебмастера откройте нужный сайт → раздел
   **«Поисковые запросы» → «Популярные запросы»**.
2. Задайте диапазон дат ровно на один календарный месяц (как для GSC —
   с 1-го по последнее число месяца).
3. Экспортируйте таблицу за этот месяц: запрос, страница (URL), показы,
   клики, CTR, позиция показа, спрос (демонстрируется как отдельная
   колонка/метрика в отчёте — см. блок «Не путать demand и shows» ниже;
   если в интерфейсе конкретного аккаунта спрос отдельной колонкой не
   показывается — оставьте `{YYYY-MM}_demand` пустой для этого месяца,
   пайплайн это допускает, см. ниже).
4. Повторите шаги 2–3 для каждого месяца, который нужен в истории
   (обычно 12+ месяцев — чем больше, тем надёжнее тренды сезонности и
   находки блока SEO).
5. Сведите все помесячные выгрузки в **одну** таблицу: одна строка на
   пару (запрос, страница), а метрики каждого месяца — отдельным блоком
   колонок `{YYYY-MM}_shows/_position/_demand/_ctr/_clicks` рядом с уже
   существующими. Если для какой-то пары (запрос, страница) в конкретном
   месяце данных не было вовсе — оставьте ячейки этого месячного блока
   пустыми для этой строки, не пишите `0`.
6. Сохраните итоговую таблицу как `webmaster_export.csv` (или то имя,
   что указано в `manual_export_file`) и положите в
   `inputs/manual_exports/webmaster/`.

Кодировка (`utf-8-sig` или `cp1251`) и разделитель (`,`, `;` или таб)
определяются автоматически — можно сохранять как выгружено, не
перекодировать вручную.

## Не путать demand и shows (частая ошибка интерпретации)

`demand` и `shows` — это **разные по смыслу метрики**, и путать их при
анализе — типичная ошибка:

- **`shows`** — сколько раз именно **ваш сайт** был показан в выдаче по
  этому запросу.
- **`demand`** — весь рыночный объём запроса в Яндексе целиком (аналог
  Wordstat), **не привязанный к конкретному сайту**. Это спрос по всей
  базе Яндекса, а не то, сколько раз показали именно вас.

Разрыв `demand` >> `shows` **не означает автоматически**, что «сайт
показывается на слишком низкой позиции». Возможные причины разрыва:
- региональное несовпадение (`demand` считается по всей базе Яндекса,
  а сайт геотаргетирован на конкретный регион);
- нормализация близких формулировок запроса под один текст;
- персонализация выдачи.

Если нужно отделить эффект позиции от прочих причин — сравнивайте разрыв
`demand`/`shows` у запросов с разной позицией (топ-3 против топ-10+):
если разрыв уже большой на топ-3 позициях, дело не в позиции сайта в
выдаче, а в одной из причин выше.

Эта путаница напрямую влияет на находки блока SEO (в частности —
проверки про спрос без посадочной страницы и сезонность), поэтому при
выгрузке **не переносите** значение `demand` в колонку `shows` и
наоборот, даже если в интерфейсе Вебмастера они стоят рядом визуально.

## Пропуски месяцев vs честный ноль

Пустая ячейка `{YYYY-MM}_shows` (и остальных метрик того же месяца) для
конкретной пары (запрос, страница) означает «в этом месяце запрос по
этой странице не показывался вовсе». Явный `0` в ячейке — это
подтверждённый Яндексом ноль (например, `demand=0`), а не отсутствие
данных. Эти два состояния нельзя смешивать: если у вас нет данных за
месяц — оставляйте ячейку пустой, не ставьте туда `0`.

Отдельно: строки, где `{YYYY-MM}_shows` равен `0`, при подготовке
`data/raw/webmaster/search_queries_popular.json` этот месяц просто
пропускается при агрегации (не влияет на среднюю позицию и спрос этой
строки) — это ожидаемое поведение парсера, а не повод переделывать
выгрузку.

## Страница (Url) — если разбивки по страницам нет

Колонка `Url` ожидается парсером (маппится на `page` в выгрузке), но
если в интерфейсе доступен только запрос без привязки к странице —
оставляйте `Url` пустой для всех строк. Пайплайн такие строки не
отклоняет (обязателен только непустой `Query`).

## column_map

Заголовки `Query`/`Url` в CSV можно переопределить под фактические
заголовки конкретного экспорта через
`clients/<name>/config.yaml` → `sources.webmaster.column_map`
(например, `{"query": "Запрос", "page": "Страница"}`). Суффиксы метрик
(`_shows`, `_position`, `_demand`, `_ctr`, `_clicks`) фиксированы
форматом и не настраиваются.
